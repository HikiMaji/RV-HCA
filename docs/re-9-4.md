# 八、还有两个统计问题，我也在代码里找到了

### “EWMA”实际上不是 EWMA

你现在：

```python
tail = values[-5:]

"ewma": float(np.mean(tail))
```

这叫：

**rolling mean / moving average（滑动平均）**

不是：

**EWMA, Exponentially Weighted Moving Average（指数加权移动平均）**。

所以之前所有写：

> EWMA

的表其实都是：

> 最近5项普通均值。

这个不影响 `latest` 的结论，但论文不能这么叫。

## 更重要：A/B/C 的 ego-history control 也不完全干净

当前 target history key 是：

```python
(
    scene,
    receiver,
    source,
    target,
    horizon
)
```

然后：

```python
error_histories_target[target_key]["ego"]
error_histories_target[target_key]["peer"]
```

都用同一个 key。

也就是说 B：

> `A + ego history`

实际上不是：

> “receiver 对这个 target 的 ego 历史难度”

而是：

> “在这个 particular peer/source 出现的情况下，这个 target 的 ego 历史”。

这把 ego baseline 也按 `source` 切碎了。

可是 ego 对 target 的预测误差，本质应该是：

```text
(scene, receiver, target, horizon)
```

不需要 peer source。

所以如果 B 的目的是控制：

> target difficulty（目标自身难度）

正确的 ego-target history 应该去掉 `source`。

而 C 的 peer history 才是：

```text
(scene, receiver, source, target, horizon)
```

否则 B 会被人为变稀疏，可能放大：

$$
AUC(C)-AUC(B)
$$

# 九、还有一个 metric 问题：不要继续把 3D 当主 Harm 指标

MTR 的 trajectory head 实际上预测的是 planar XY（平面二维位置）。

你们在 export 时人为：

```python
center_z = ...
source_xyz = concatenate(...)
```

也就是未来所有时刻的 z 都复制当前 `center_z`。

然后 `recompute_mtr_ledger_errors.py` 却算：

```python
np.linalg.norm(aa[:3] - bb[:3])
```

即：

# 3D Euclidean error

这对绝对 55m 不是主因。

但对：

$$
harm =
peer\_error >
ego\_error + 0.1m
$$

可能很重要。

因为你 epsilon 才：

$$
0.1m
$$

一点 detector z jitter（高度抖动）就可能改变标签。

最终 RV-HCA 主实验应该用：

# **XY 2D error**

和官方 MTR trajectory metric 对齐。

3D 可以作为 sensitivity analysis（敏感性分析），不是主指标。
